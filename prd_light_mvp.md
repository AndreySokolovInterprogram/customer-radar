# ТЕХНИЧЕСКОЕ ЗАДАНИЕ (PRD + ТЗ)
**Продукт:** VK Mini App «НейроКонт: ИИ-радар конкурентов» (Модуль 1 платформы НейроКонт / Markly)  
**Формат релиза:** Production-Ready Light MVP для прохождения модерации каталога VK Mini Apps  
**Целевая инфраструктура:** Бюджетный VPS-сервер (1 vCPU, 512 МБ – 1 ГБ RAM, без GPU)  
**База разработки:** Доработка существующего репозитория проекта (`index.html`, `api/main.py`, `api/cache.db`, `nginx.vk.markly.ru.conf`)  
**Трудоемкость реализации:** 1 рабочий день (8 часов) силами одного разработчика

## 1. Главные архитектурные решения (Адаптация под малый сервер и отсутствие готовой LSTM)

### 1.1. Использование существующего проекта как базы (Zero-Build Frontend + FastAPI)
Вместо создания тяжелого окружения с нуля за основу берется текущая структура вашего репозитория (`vk.markly.ru`), так как она идеально подходит под слабый сервер и быструю модерацию:
* **Frontend без тяжелой сборки (`index.html`):** Одностраничное приложение (SPA) в одном файле `index.html` с подключением `@vkontakte/vk-bridge` и стилизацией под дизайн-систему VKUI (с поддержкой светлой и темной тем ВК через CSS-переменные). Это избавляет сервер от установки Node.js, сборки `node_modules` и экономит 100% оперативной памяти на этапе CI/CD (`.github/workflows/deploy.yml`).
* **Готовые юридические страницы (`privacy.html` и `terms.html`):** Уже присутствуют в корне проекта и раздаются через `nginx.vk.markly.ru.conf`. Ссылки на них обязательны при подаче заявки на модерацию в кабинет ВК.
* **Локальный SQLite-кэш (`api/cache.db` + `api/refresh_cache.py`):** Результаты парсинга демо-пресетов и частых запросов кэшируются в SQLite. Даже если VK API временно ответит ошибкой или лимитом во время проверки модератором, бэкенд мгновенно отдаст валидные данные из `cache.db`.

### 1.2. Отказ от тяжелого PyTorch/LSTM в пользу легковесного ML-конвейера «на лету» (Cold-Start AI + Active Learning)
Поскольку готовых обученных весов LSTM нет, а установка `torch` на сервер требует ~1.5 ГБ диска и ~400 МБ RAM в простое, нейросетевой блок заменяется на **гибридный легковесный ML-движок на базе `scikit-learn` (TF-IDF + SVD/Латентный вектор + Логистическая регрессия с Active Learning)**:
1. **Не требует предварительного датасета и предобучения:** Модель векторизует выборку из 150–300 найденных групп прямо в момент запроса за $15\text{–}30\text{ мс}$ на 1 ядре CPU.
2. **Потребление памяти до 50 МБ RAM:** Весь бэкенд вместе с FastAPI и `scikit-learn` занимает минимум ресурсов и стабильно работает на самом дешевом VPS.
3. **Полное сохранение научной и продуктовой логики (Скоринг + Active Learning):** Алгоритм формирует латентный вектор признаков каждого сообщества $\mathbf{h}_i \in \mathbb{R}^{32}$, вычисляет вероятность релевантности $P_{rel} \in [0; 1]$, выделяет пограничные случаи $P_{rel} \in [0.40; 0.65]$ и за $5\text{ мс}$ пересчитывает веса классификатора (`LogisticRegression` / `SGDClassifier`) по кликам пользователя в блоке Active Learning.

### 1.3. Архитектура входа и работы с VK API без запроса прав у пользователя
Для 100% прохождения модерации приложение **не запрашивает окна разрешений (scopes)** у пользователя:
* Ввод осуществляется через текстовое поле для ссылки или `screen_name` любой группы ВК (например, `https://vk.com/dodo` или `dodo`) + **3 кнопки быстрых демо-примеров** («Доставка еды», «Фитнес-клуб», «Автосервис»).
* **Важная деталь реализации VK API:** Методы `utils.resolveScreenName` и `groups.getById` работают с сервисным ключом (`VK_SERVICE_TOKEN`), но метод поиска `groups.search` в VK API требует пользовательский токен. Чтобы не пугать пользователя и модератора окном авторизации, все запросы к `groups.search` выполняются **на бэкенде (`api/main.py`)** через технический токен `VK_USER_TOKEN`, указанный в `.env` на сервере, с автоматическим кэшированием ответов в `api/cache.db`.

## 2. Математическая и алгоритмическая спецификация ИИ-модуля (без готовой LSTM)

Весь ML-пайплайн реализуется в `api/main.py` (или `api/ml_engine.py`) с использованием стандартных библиотек `scikit-learn` и `numpy`.

### 2.1. Алгоритм определения ниши и генерации ключевых слов (`/api/v1/detect-niche`)
Работает полностью автономно без платных внешних LLM (с возможностью опционального подключения внешнего LLM API при наличии ключа):
1. **Очистка текста:** Из полей исходной группы `name`, `activity`, `status`, `description` удаляются URL-ссылки, телефоны, эмодзи, спецсимволы и русские стоп-слова (предлоги, союзы, слова «группа», «сообщество», «официальный», «вконтакте»).
2. **Определение города (`detected_city`):** Берется из поля `city.title` метаданных ВК. Если поле пустое — ищется совпадение по встроенному словарю крупных городов РФ в названии и описании группы.Название города удаляется из ключевых фраз, чтобы поиск не сужался раньше времени.
3. **Формирование названия ниши (`niche_title`):** Конкатенация системной категории ВК (`activity`) и очищенного ядра названия группы (текст до разделителей `|`, `-`, `/`).
4. **Экстракция 5–8 ключевых запросов (`keywords`):**
   * Запрос №1: Очищенная категория `activity` (если она не общая, т.е. не «Блог» или «Публичная страница»).
   * Запрос №2: Очищенное ядро названия группы.
   * Запросы №3–7: Топ биграмм и униграмм с наибольшим весом TF-IDF, извлеченных из `name + status + description` с помощью `TfidfVectorizer(ngram_range=(1, 2))`.

### 2.2. Первичный ИИ-скоринг кандидатов (Cold-Start Scoring)
Для каждого из $N$ найденных сообществ-кандидатов ($N \in [100; 300]$) формируется текстовый документ:
$$D_i = \text{clean}(\text{name}_i + \text{« »} + \text{activity}_i + \text{« »} + \text{description}_i)$$

1. **Гибридная TF-IDF векторизация (Слова + Символьные N-граммы):**
   Чтобы не устанавливать тяжелые морфологические анализаторы (`pymorphy2` / `natasha`), используется `TfidfVectorizer(analyzer='char_wb', ngram_range=(3, 5), max_features=1500)`. Символьные 3–5-граммы идеально улавливают корни русских слов с любыми окончаниями («доставк», «пицц», «ролл»).
2. **Сжатие в скрытое состояние (Аналог скрытого слоя $\mathbf{h}_i$):**
   Матрица TF-IDF сжимается через `TruncatedSVD(n_components=32)` в плотные эмбеддинги $\mathbf{h}_i \in \mathbb{R}^{32}$.
3. **Вычисление базовой близости $S_{sim, i} \in [0; 1]$:**
   Вычисляется косинусная близость (`cosine_similarity`) между вектором каждого кандидата $\mathbf{x}_i$ и **Эталонным вектором ниши** $\mathbf{x}_{ref}$ (сформированным из текста исходной группы + утвержденных пользователем ключевых слов `niche_title + keywords`).
4. **Лексический фильтр «Коммерция vs Шум» ($S_{comm, i}$):**
   * *Словарь коммерческих маркеров (+0.15 к весу):* `доставка, заказать, заказ, цена, цены, прайс, стоимость, купить, магазин, услуги, запись, записаться, каталог, меню, работаем, адрес, акция, скидка, производство, сервис, студия, клиника, клуб`.
   * *Словарь информационного шума (-0.35 к весу):* `подслушано, барахолка, объявления, отдам даром, мемы, приколы, юмор, цитаты, статусы, фан, сериал, фильмы, игры, знакомства, чат, черное и белое, чс`.
   * *Бонус за совпадение категории ВК (+0.15 к весу):* если `activity` кандидата совпадает с `activity` исходной группы.
5. **Итоговая вероятность релевантности $P_{rel, i}$:**
   Значения нормализуются через сигмоидальную функцию калибровки в диапазон $[0.05; 0.99]$:
   $$P_{rel, i} = \text{clip}\left( \frac{1}{1 + \exp(-6 \cdot (S_{sim, i} + S_{comm, i} - 0.35))}, 0.01, 0.99 \right)$$

### 2.3. Пересчет с Active Learning за 5 мс (`/api/v1/classify-groups`)
1. **Отбор пограничных групп:** Группы с высокой неопределенностью $P_{rel, i} \in [0.40; 0.65]$ (до 8 штук) возвращаются в массиве `uncertain_for_active_learning`.
2. **Дообучение на лету по кликам эксперта:**
   Когда пользователь размечает 1 или более групп как «Конкурент» ($y = 1$) или «Не конкурент» ($y = 0$) и отправляет `active_learning_feedback`:
   * Формируется обучающая мини-выборка из размеченных пользователем групп + 3 «якорных» лидеров ($P_{rel} > 0.85$ с меткой $y=1$) + 3 «якорных» шумовых групп ($P_{rel} < 0.20$ с меткой $y=0$).
   * На сжатых векторах $\mathbf{h}_i$ мгновенно обучается `LogisticRegression(C=1.0)` из `scikit-learn`.
   * Новая оценка вычисляется как взвешенная комбинация базового скора и предсказания логистической головы:
     $$P_{rel, i}^{new} = 0.4 \cdot P_{rel, i}^{base} + 0.6 \cdot P_{LR}(\mathbf{h}_i)$$

## 3. Пользовательский сценарий (User Flow — 3 экрана)

Интерфейс строится в 3 последовательных экрана (таба/панели) с поддержкой светлой и темной темы клиента ВКонтакте и хранением сохраненных подборок.

### Экран 1: Ввод сообщества и определение предметной области (Шаги 1 и 2)
1. **Шапка и навигация:** Название «НейроКонт: ИИ-радар», кнопка переключения в раздел «Мои подборки» (сохраненные в `VKWebAppStorage`).
2. **Блок ввода:**
   * Текстовое поле для ссылки или короткого имени группы ВК (`https://vk.com/dodo`, `dodo`, `club12345`).
   * Кнопка «Определить нишу».
   * **3 чипса быстрых демо-примеров (Киллер-деталь для модерации):** «🍕 Доставка еды», «🏋️ Фитнес-клуб», «🔧 Автосервис». Клик по чипсу мгновенно подставляет проверенную ссылку и запускает анализ.
3. **Карточка распознанной группы и ручная корректировка (Editable State):**
   * Отображается аватарка, название, категория и число подписчиков исходной группы.
   * Редактируемое текстовое поле **«Предметная область»** (например: *«Доставка пиццы и роллов, общепит»*).
   * Редактируемый блок тегов **«Ключевые запросы для поиска конкурентов»** (5–8 тегов с возможностью удалить тег крестиком или добавить свой через поле ввода).
   * Главная кнопка действия: **«Найти и классифицировать конкурентов (ИИ)»**.

### Экран 2: ИИ-классификация и блок Active Learning (Шаг 3)
1. **Индикатор прогресса:** При запуске поиска показывается аккуратный лоадер со статусом: *«Собираем кандидатов из ВК и фильтруем информационный шум...»*.
2. **Интерактивный блок «Уточнить ИИ-отбор (Active Learning)»:**
   * Показывается над результатами (или промежуточным шагом), если найдены пограничные сообщества с $P_{rel} \in [0.40; 0.65]$.
   * Содержит 5–8 компактных карточек сомнительных групп с двумя быстрыми кнопками на каждой: **«👍 Конкурент»** (`label: 1`) и **«👎 Шум»** (`label: 0`).
   * Кнопка **«Пересчитать выдачу с учетом ответов»** (мгновенно обновляет ранжирование) и кнопка **«Пропустить / Показать результаты сразу»**.

### Экран 3: Дашборд релевантных конкурентов с фильтрацией и экспортом (Шаг 4)
1. **Сводная плашка (Summary Banner):**
   * *«Проверено групп: 215 • Отобрано ИИ: 64 • Отсеяно шума: 151»*.
2. **Панель фильтрации и сортировки (выполняется мгновенно на клиенте в JS):**
   * **Аудитория (`members_count`):** Все / До 5 тыс. / 5–50 тыс. / 50–200 тыс. / 200 тыс.+
   * **Порог уверенности ИИ (`lstm_score`):** Все релевантные ($\ge 50\%$) / Только прямые конкуренты ($\ge 80\%$).
   * **География (`city`):** Все города / Только город исходной группы.
   * **Доступность:** Переключатель «Только открытые группы (`is_closed == 0`)».
   * **Сортировка:** По релевантности ИИ (по умолчанию) / По размеру аудитории.
3. **Список карточек конкурентов:**
   * Аватарка (`photo_100`), название, галочка верификации, город, категория (`activity`) и точное число подписчиков.
   * Цветной бейдж релевантности: зеленый при $\ge 80\%$ (*«96% • Прямой конкурент»*), синий/желтый при $50\text{–}79\%$ (*«68% • Смежная ниша»*).
   * Чекбокс выбора группы (по умолчанию выбраны все отфильтрованные) и ссылка «Открыть в ВК».
4. **Панель бизнес-действий (фиксированная внизу экрана):**
   * **«Скопировать ID / Ссылки (CSV)»** — копирует список `group_id` или ссылок отобранных конкурентов в буфер обмена через `vkBridge.send('VKWebAppCopyText')` с уведомлением `Snackbar` (*«Скопировано 64 сообщества для парсинга и таргета»*).
   * **«Сохранить подборку»** — сохраняет результат в `VKWebAppStorageSet` (и `localStorage` как фолбэк), чтобы пользователь мог вернуться к нему во вкладке «Мои подборки».

## 5. Спецификация API и контракты данных (Backend <-> Frontend)

Для максимального упрощения фронтенда и защиты от ошибок CORS/токенов ВК, бэкенд берет на себя обращение к VK API, если фронтенд передает просто ссылку на группу или ключевые слова. При этом сохраняется полная обратная совместимость со структурой из исходного ТЗ.

### Эндпоинт 1: `POST /api/v1/detect-niche`
Принимает либо `screen_name`/ссылку на группу (и сам запрашивает метаданные в VK API / `cache.db`), либо уже готовые метаданные группы, и возвращает предметную область + ключевые слова.

**Запрос (Вариант А — просто по ссылке или пресету, рекомендуется):**
```json
{
  "group_input": "https://vk.com/dodo"
}
```
**Запрос (Вариант Б — с готовыми метаданными):**
```json
{
  "group_id": 123456,
  "name": "Суши Мастер | Доставка роллов Пермь",
  "activity": "Доставка еды",
  "description": "Бесплатная доставка суши, роллов и вок в Перми за 45 минут. Скидка 15% в день рождения."
}
```

**Ответ (`200 OK`):**
```json
{
  "target_group": {
    "id": 25557243,
    "name": "Додо Пицца Россия",
    "screen_name": "dodo",
    "activity": "Ресторан",
    "description": "Доставка пиццы за 60 минут или пицца бесплатно...",
    "members_count": 2150400,
    "city": {"id": 1, "title": "Москва"},
    "photo_100": "https://..."
  },
  "niche_title": "Ресторан • Доставка пиццы и еды",
  "detected_city": "Москва",
  "keywords": [
    "доставка пиццы",
    "пиццерия",
    "заказать пиццу",
    "доставка еды",
    "горячая пицца",
    "ресторан доставка"
  ]
}
```

### Эндпоинт 2: `POST /api/v1/classify-groups`
Принимает утвержденную пользователем предметную область, ключевые слова, опциональные метки Active Learning и (опционально) массив `candidate_groups`. Если `candidate_groups` не передан с клиента, бэкенд сам собирает кандидатов через `groups.search` + `groups.getById` (с кэшированием в `api/cache.db`), прогоняет их через ML-конвейер и возвращает ранжированный список.

**Запрос:**
```json
{
  "target_group_id": 25557243,
  "niche_title": "Ресторан • Доставка пиццы и еды",
  "detected_city": "Москва",
  "keywords": ["доставка пиццы", "пиццерия", "доставка еды"],
  "active_learning_feedback": [
    {"group_id": 998811, "label": 1},
    {"group_id": 776655, "label": 0}
  ],
  "candidate_groups": []
}
```

**Ответ (`200 OK`):**
```json
{
  "total_checked": 185,
  "relevant_count": 64,
  "noise_filtered": 121,
  "uncertain_for_active_learning": [
    {
      "id": 554433,
```

## 6. Схема кэширования в SQLite (`api/cache.db`) и роль `refresh_cache.py`

Чтобы приложение работало мгновенно (за $0.1\text{ с}$) на демо-примерах для модератора и не упиралось в лимиты VK API:
1. В `api/cache.db` создаются 2 простые таблицы:
   * `resolved_groups (screen_name TEXT PRIMARY KEY, group_json TEXT, updated_at INTEGER)` — кэш метаданных целевых групп.
   * `keyword_search_cache (keyword TEXT PRIMARY KEY, groups_json TEXT, updated_at INTEGER)` — кэш результатов `groups.search` + `groups.getById` по ключевому слову (время жизни TTL = 7 дней).
2. Скрипт `api/refresh_cache.py` запускается при деплое (или по крону) и заранее прогревает кэш для 3 демо-пресетов («Доставка еды», «Фитнес-клуб», «Автосервис»). Если на сервере вообще не задан токен ВК, `api/main.py` отдает предзаготовленные реальные данные из `cache.db` — приложение **никогда не упадет с ошибкой 500** перед модератором.

## 7. Требования для гарантированного прохождения модерации VK Mini Apps

1. **Безусловный вызов `VKWebAppInit`:** При старте `index.html` сразу вызывается `vkBridge.send('VKWebAppInit')`.
2. **Поддержка системной темы ВК:** Подписка на событие `VKWebAppUpdateConfig` автоматически переключает тему (`vkui--vkBase--light` / `vkui--vkBase--dark`), чтобы текст был контрастным и в светлой, и в темной теме мобильного приложения ВК.
3. **Безопасные отступы (`Safe Area` и системные кнопки):** Верхняя шапка приложения имеет правый отступ (`padding-right: 96px`), чтобы заголовок и кнопка «Мои подборки» не перекрывались системным блоком ВК («три точки» и «крестик закрытия»).
4. **Отсутствие тупиковых кнопок:** В интерфейсе нет ни одной кнопки «Скоро» или «В разработке». Все элементы (3 демо-чипса, редактирование тегов, Active Learning, 4 фильтра, сортировка, копирование ID/CSV, сохранение в «Мои подборки» и переход в группы ВК) полностью функциональны.
5. **Онбординг при первом входе:** При первом запуске (проверка флага в `VKWebAppStorage` / `localStorage`) показывается компактная карточка онбординга в 3 строки с описанием ценности сервиса и кнопкой «Начать работу».
6. **Нативная обработка ошибок:** При вводе некорректной ссылки или пустого запроса всплывает аккуратное уведомление (Snackbar): *«Не удалось распознать открытое сообщество. Проверьте ссылку или выберите один из демо-примеров ниже»*.

## 8. Почасовой план реализации (8 часов)

* **Часы 1–2 (Бэкенд: каркас FastAPI + SQLite-кэш + интеграция VK API):**
  Реализация `api/main.py` с подключением к `api/cache.db`. Настройка получения метаданных группы и пакетного поиска кандидатов через VK API с фолбэком на локальный кэш.
* **Часы 3–4 (Бэкенд: легковесный ML-движок без готовой LSTM):**
  Реализация в `api/main.py` экстрактора ключевых слов (`detect-niche`) и пайплайна `TfidfVectorizer` + `TruncatedSVD` + лексический фильтр коммерции/шума + пересчет `LogisticRegression` для Active Learning (`classify-groups`). Запуск `api/refresh_cache.py` для наполнения `cache.db` демо-примерами.
* **Часы 5–6 (Фронтенд `index.html`: Экраны 1, 2 и 3):**
  Верстка и связка с API в `index.html`: Экран 1 (ввод ссылки, 3 демо-чипса, редактирование ниши и чипсов ключевых слов), Экран 2 (витрина пограничных групп Active Learning с кнопками «Конкурент» / «Шум»), Экран 3 (дашборд с 4 фильтрами, сортировкой и карточками сообществ).
* **Часы 7–8 (Интеграция VK Bridge, проверка по чек-листу модерации и деплой):**
  Подключение `VKWebAppInit`, `VKWebAppCopyText` (экспорт CSV/ID), `VKWebAppStorageSet` / `VKWebAppStorageGet` (раздел «Мои подборки»), адаптация под темную тему ВК и деплой на сервер через `nginx.vk.markly.ru.conf` / GitHub Actions.
