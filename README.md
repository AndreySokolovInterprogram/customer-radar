# Клиентский Радар

Живая витрина данных NCA-RS (VK Mini App, [app54674554](https://vk.com/app54674554)) — статистика по собранным сообществам, постам и профилям пользователей в четырёх предметных областях исследования, с разбором по области/городу и топ-5 постов по вовлечённости.

## Статус

Задеплоено на `vk.markly.ru`. VK Bridge подключён (`VKWebAppInit` + `VKWebAppGetUserInfo` — показываем имя вошедшего пользователя, без серверной проверки подписи launch params). Интерактивный разбор по области и городу читает данные из `api/`.

## Архитектура

- `index.html` — статическая страница + JS, ходит в `/api/*` (тот же домен, проксируется nginx).
- `api/main.py` — FastAPI, читает готовые агрегаты из локального SQLite-кэша (`cache.db`), не трогает прод-БД на каждый запрос.
- `api/refresh_cache.py` — фоновый цикл (systemd `customer-radar-refresh.service`), раз в 15 минут пересчитывает агрегаты из прод-БД через read-only роль `radar_readonly` и пишет в `cache.db`. Прямые агрегатные запросы по ~1.3М постов на каждый HTTP-запрос были неприемлемо медленными (десятки секунд) — поэтому кэш, а не live-запросы.
- Postgres доступен API только на чтение (`radar_readonly`, GRANT SELECT на 4 таблицы) — ни сама витрина, ни фоновый пересчёт не могут ничего изменить в проде.

## Деплой

`.github/workflows/deploy.yml` при каждом push в `main`:
1. синхронизирует `index.html` и `api/` на сервер по SSH (пользователь `radar`, без sudo, ограничен `/opt/customer-radar`);
2. перезапускает `customer-radar-api` и `customer-radar-refresh` через узко ограниченный `sudo` (только эти два `systemctl restart`, ничего больше — см. `/etc/sudoers.d/radar-restart-services` на сервере).

Секреты репозитория:

- `SSH_HOST`, `SSH_USER`, `SSH_PRIVATE_KEY` — уже настроены.
- `VK_SECURE_KEY` — защищённый ключ приложения из VK Developers (Настройки → Ключи доступа). Уже добавлен — деплой кладёт его в `/opt/customer-radar/.env` на сервере (пока не используется кодом — задел на серверную проверку подписи VK Bridge).

## Известные ограничения

- Город/регион собирается только для части сообществ (поле `city` в `groups.getById` раньше не запрашивалось вообще — добавлено в vk-research-collector 2026-09-04, бэкафилл идёт в фоне через обычный TTL-цикл обновления метаданных).
- Кэш обновляется раз в 15 минут — не секундная свежесть, но для этой витрины достаточно.
